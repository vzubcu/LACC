# CR-3B — Answer-Level Disclosure Gate (develop implementation)

**Status:** Node CLI and agent-bridge behavior authored in develop; **tests
NOT EXECUTED**, real generated host-response checks **NOT PERFORMED**.
**Target:** mandatory RD-5/CR-5 acceptance before any main promotion.
Last updated: 2026-11-11.

**Community feedback (Exori AI):** if a response relies on a topic whose
earlier memory was withheld, users must be told **in the answer**, not only
via internal health or recall diagnostics.

## What is implemented

The new, offline Node.js 22+ command runs existing trust-filtered `search`
with normalized CR-1/CR-2 evidence (opt-in dependency checks with `--deps`):

```powershell
node <skill_dir>/scripts/lacc.mjs answer-disclosure . --query "login policy" --json
node <skill_dir>/scripts/lacc.mjs answer-disclosure . --query "login policy" --claim "Login policy is secure" --deps --json
node <skill_dir>/scripts/lacc.mjs answer-disclosure . --query "login policy" --response-file draft-answer.txt --json
```

**Run before composing a material response** on recalled project behavior.
The agent must inspect current source and tests before making definitive
current-behavior claims. A CLI candidate is not proof of semantic relevance.

- Reuses the **existing** search, Git verifier, CR-1 normalized findings
  and CR-2 evidence chains; no second trust engine. The command is read-only
  by default. Optional `--cache` with explicit `--deps` follows RD-4's
  private-cache behavior.
- A matched excluded fact produces a bounded candidate with a stable finding
  ID, kind, safe cited/changed paths, recorded Git revision (when known),
  relation/coverage scope and a **canonical suggested warning**.
  No raw memory claim, source code, secret or query/claim text is echoed.
- Relevance is **lexical matching**, not a semantic determination:
  `--query` selects task-related facts using existing search and `--claim`
  optionally flags overlap with safe evidence metadata. The agent must
  decide whether a candidate materially intersects the answer. A globally
  stale but unmatched fact does not prompt an unrelated warning.
- Warnings are grouped into one suggested paragraph. Repeated findings
  share stable IDs and the output is bounded (default 4 candidates,
  optional `--limit 1..10`).
- Incomplete inventory, invalid facts, truncated diagnostics, limited
  candidate verification or output truncation remain explicitly incomplete.
  Insufficient output budget fails closed instead of reporting clean.
- Native bridges generated by `init` for Codex, Claude, Gemini and Roo
  instruct the agent to run the command where material and include the
  warning **in its actual answer** before or together with the affected
  conclusion, or use a faithful concise equivalent. Re-run `init` on
  existing projects to refresh marked rules.

The response-level fields deliberately distinguish the states:

`diagnostics_generated: true` means only a local report was produced.
`warning_in_agent_response: "not-observed"` means this CLI cannot see
what the agent sent. `host_delivery_observed: "not-observed"` and
`user_delivery: "not-observed"` remain unchanged without trusted host
evidence. No system notification, response interception or receipt exists.

## Optional supplied-response audit (not a host hook)

With `--response-file draft-answer.txt`, the CLI reads an existing,
safe, project-relative regular UTF-8 file (maximum 64 KiB) and checks
for the **exact canonical suggested warning**. This can catch an omitted
warning in an explicitly provided draft. Exit code 1 means a required
canonical warning was missing; 0 means no such omission was detected,
**not** that the actual host answer was complete or shown.
Other command/IO errors fail with exit code 2.

A translated, paraphrased or differently worded but adequate warning
does **not** satisfy this narrow exact-text checker. A developer could
supply unrelated text. Thus it cannot certify semantic adequacy, host
response emission or user visibility. Independent real-agent acceptance
must inspect actual output. The command does not write a draft file or
record a synthetic host acknowledgment.

## Decision contract

- `review-for-answer`: at least one query-matched excluded fact found.
  If it materially intersects the answer, use
  `suggested_answer_warning` or a faithful explanation, then inspect
  current source/tests.
- `incomplete-no-candidate-certification`: no candidate emitted but the
  bounded scan was incomplete. Do **not** infer verified absence.
- `no-matched-exclusion-observed`: no excluded fact appeared in the
  **checked, lexically matched** search diagnostics. Not a repository-wide
  or semantic clean bill.

Each candidate includes `finding_id`, `kind`, `relevance`,
`materiality: "agent-must-confirm"`, `checked_evidence` and
`requires_current_code_review`. The CLI emits a proposed warning,
never an automatically delivered one.

Source-path privacy is conservative: unsafe, secret-like, overlong or
absolute paths are omitted. If no safe path exists, the warning says
so instead of inventing checked evidence. Git drift indicates possible
staleness, **not** proof that the remembered assertion is false.

## Deferred release-blocking acceptance

The authored suite `tests/test_answer_level_disclosure.mjs` covers
direct and indirect drift, irrelevant questions, keyed conflicts,
missing Git, truncated scans, privacy, explicit answer-file audit,
path safety, no memory changes and all four instruction bridges.

**Tests are not executed in the implementation-first workflow.**
The release gate must run this suite on native Windows, Linux and
macOS, plus real answer-level sessions in Codex, Claude, Gemini and Roo
where their supported interfaces permit. Unavailable combinations are
UNVERIFIED. Inspect **actual agent output**, not just CLI JSON or a supplied
file. Missing material warnings FAIL acceptance. Distinguish observed
agent output from independently trusted host delivery.

## Non-goals

No automatic memory correction, trusted-fact promotion, semantic conflict
proof, universal host interception, popup, telemetry, cloud service,
synthetic receipt or sending private memory to a service.
