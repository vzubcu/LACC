# Lean Context Memory v2.3 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; implement and verify tasks in this session.

**Goal:** Implement the approved bounded, evidence-based memory workflow.
**Architecture:** Existing Bash orchestration, Markdown facts with source/commit provenance, read-only Python validation, and bounded textual dependency searches.
**Tech Stack:** Bash, Git, ripgrep/grep, Python 3 standard library.
**Spec:** ../specs/2026-11-02-memory-v23-design.md

## Global Constraints
- No new packages/services and no automatic semantic deletion.
- Index 60 lines; checkpoint 30 lines/2048 bytes; topic 4096 bytes; topics aggregate 16384 bytes; topic limits configurable.
- Report incompleteness whenever search or diagnostic output is truncated.
- Preserve existing memory on initialization; do not stamp a failed health check.

## Review Focus
- Paths with spaces, source renames/deletions, and files outside project root.
- Invalid or missing commits/config/metadata and repositories without commits.
- Dirty, staged, untracked and non-Git changes.
- Source/memory symlinks, non-UTF8 inputs, and inherited read-only behavior.
- High-fanout searches, missing ripgrep, and output truncation.
